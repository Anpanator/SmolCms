== Database and persistence

SQLite is the default runtime database. Its schema covers users and sessions,
content and migration tracking, images, tags/categories and image-tag links,
tag suggestions and approvals, and a limited image-tag audit log.
`TagService` coordinates tags, categories, image associations, and usage
counts; suggestion and approval records are handled by the tag-suggestion
services.

`private/init/init.sql` is a MySQL reference, not a parity guarantee: it lacks
the image table, and the checked-in migrations use SQLite-specific SQL. The
SQLite schema in `private/init/init_sqlite.sql` is the supported default.

Entity services map database columns to typed entities, including dates and
backed enums. `AccessLevel` is persisted by its backing value and represents a
user's authorization role. Missing or `NULL` database fields are passed as
`null` during hydration, so constructors must accept null for fields that can
be absent or nullable in the schema.

`QueryCriteria` provides a small parameterized query interface:

[source,php]
----
$criteria = (new QueryCriteria())
    ->select(UserEntity::class)
    ->andWhere('id = :id')
    ->withParameters(['id' => $id])
    ->maxResults(1);
----

`--migrations` scans pending, non-empty `.sql` files in filename order and
records each successfully executed filename in the `migration` table; see
<<_cli_commands>>.
