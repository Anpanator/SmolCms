== CLI Commands

The application supports CLI commands through `php src/app.php`.
Flags use a `--` prefix.
Non-flag tokens following a recognized flag are collected as that flag's `$arguments` array in `$argv` order and passed to `execute()`; separate arguments with spaces and quote values containing spaces.
Currently only `--generate-migration` uses `arguments[0]`; `--migrations` and `--reset-db` ignore arguments.
Recognized command executors are registered positionally as parameters to `CliCommandHandler` in `CoreServiceConfiguration`.
A single invocation may contain several distinct flags; each executor whose flag is present runs at most once, in the order its flag first appears on the command line.
Repeating a flag does not re-run it; the last occurrence's arguments win.
`--noconfirm` never runs as an executor.

`runCli()` exits `0` whenever `PHP_SAPI` is `cli` (even when only printing the command list for unknown flags), so `runCgi()` only runs under a non-CLI SAPI.
Functional tests use `TestContextService` and force non-CLI mode for `simulateRequest()`.

To add a command, add a case to the `CliCommandFlag` enum, create a class implementing `CliCommandExecutor`, and add the executor to the `CliCommandHandler` service definition.
The enum `value` is the literal flag text without `--`.
The executor's `handles()` must return the new case and `helptext()` supplies the command-list output.
When the executor has builtin or string constructor dependencies, add its own `Service` definition, as done for `MigrationsExecutor`.
`--noconfirm` is a global modifier consumed by the handler; it is not an executor.

=== Available commands

|===
| Flag | Description

| `--generate-migration "<description>"`
a|Creates a timestamped migration skeleton in `private/sql`, named `YYYY-MM-DD_HH-MM-SS__<sanitized-description>.sql`, where `<sanitized-description>` replaces every `[^a-zA-Z0-9_-]` character with `_`, trims leading and trailing `_`, and falls back to `migration`.
The file content is `-- Migration: <original description>\n`.
Only the first argument is used; extra tokens are ignored.
An empty or missing description prints the usage text and creates nothing.
Generation does not execute the migration.

| `--migrations`
a|Scans `private/sql` non-recursively via `FileSystemAccessService::listFiles` for regular allowed files ending case-sensitively in `.sql`, sorts them by filename, and executes files not recorded in the `migration` table.
Comparison and recording use the `basename()` against `migration.filename`.
Successful migrations are recorded; already-recorded files are skipped, and empty files (including whitespace-only files) are skipped without being recorded but still count as pending for the confirmation prompt.
Confirmation lists the pending basenames and is required only when pending files exist, unless `--noconfirm` is supplied; only `y` (case-insensitive) proceeds — any other answer, including `yes`, aborts.
A failed migration is not recorded, later files are not attempted, and `Migrations complete.` is not printed.
Arguments to `--migrations` are ignored, and a missing directory prints an error.

| `--reset-db`
a|Destructively drops tables and reloads the driver-specific schema: SQLite drops all tables except `sqlite_%`, while MySQL drops all tables in `DATABASE()`.
The default SQLite configuration reloads `private/init/init_sqlite.sql`.
The MySQL branch sets `FOREIGN_KEY_CHECKS = 0` before the drops and re-enables it to `1` after the drops and before reloading `private/init/init.sql`.
Confirmation is required unless `--noconfirm` is supplied.
Unlike `--migrations`, the prompt is unconditional even with no tables; with no tables it prints `No tables to drop.` and still reloads the schema.

| `--noconfirm`
a|Modifier for `--migrations` and `--reset-db`; suppresses their confirmation prompts.
It does not execute by itself and has no effect on `--generate-migration`.
|===

=== Usage examples

Generate a migration file:

`php src/app.php --generate-migration "add users table"`

Edit the generated SQL file, then run pending migrations with confirmation:

`php src/app.php --migrations`

Run pending migrations without confirmation:

`php src/app.php --migrations --noconfirm`

Reset the database with confirmation:

`php src/app.php --reset-db`

Reset the database without confirmation:

`php src/app.php --reset-db --noconfirm`

`--noconfirm` may appear before or after the command; its position does not affect suppression, but non-flag tokens immediately after `--noconfirm` are consumed as its ignored arguments.
If no executable command flag is provided, such as with no arguments, an unknown flag, or only `--noconfirm`, the handler prints the available-command list.
Unknown `--` flags are ignored and reset the current flag, so following bare tokens are also ignored until the next recognized flag.
Bare tokens before any recognized flag (or after an unknown flag) are ignored; bare tokens after a recognized flag become that flag's arguments.
