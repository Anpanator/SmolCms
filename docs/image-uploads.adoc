== Image uploads

Authenticated users can select multiple images. The browser uploads each
sequentially in a multipart `POST /upload-image` request using field `image[]`.
The server recognizes PNG, JPEG, AVIF, and WebP by signature and verifies that
each image can be decoded. Dimensions are checked before GD decoding: neither
side may exceed 16,384 pixels and the image may not exceed 20 million pixels.
The Docker PHP/Nginx configuration allows up to 100 MB per file and request;
manual hosts must set compatible PHP and web-server limits.

Upload validation decodes the image to confirm it is readable and capture its
dimensions, but stores the original bytes unchanged. Stored files are
content-addressed by SHA-256. A new image starts pending and is tagged `tagme`.

=== Processing and delivery

The asynchronous worker re-decodes each original and creates three re-encoded
variants: a public AVIF thumbnail, a private WebP viewing sample, and a private
download. Downloads remain in the source format except PNG, which becomes
pixel-lossless WebP. The worker moves the image to the accepted collection or
moderation queue according to the uploader's role, then removes the original
when no other image record references it.

Run `php src/app.php --process-images 100` to process a batch; Docker runs the
same command periodically in the background. Failed images remain pending for
retry. The original is never served to users. Thumbnails are static public
files. Accepted-image details and viewing samples are accessible anonymously;
viewing and download files are delivered through internal Nginx locations and
`X-Accel-Redirect`. Downloads require authentication.

The public `GET /api/images` list contains accepted images. Accepted-image
details are public; non-accepted details, samples, and downloads remain
restricted by the image access policy. Authenticated users can access their own
pending-review details and their own or `tagme`-tagged pending-review samples
and downloads; `MOD` and higher can access all image states. Tag input is capped
at 2,048 characters and 20 names, with a maximum of 100 characters per tag.

`GET /api/image/detail?id=...` returns details for accepted images anonymously;
pending-review details require the uploader or a moderator. The sample and
download endpoints are `GET /api/image/sample` and `GET /api/image/download`;
sample access follows the image policy, while downloads always require
authentication. They deliver files through `X-Accel-Redirect`. Moderators use `GET /api/review/queue`,
`POST /api/review/approve`, and `POST /api/review/reject`. Approval moves a
pending-review image to accepted. Rejection deletes its row and attempts to
delete unreferenced files instead of assigning a rejected status; a
content-addressed file is retained while another image record references it.
