== Image uploads

Users with `NOVICE` or higher (`401` when anonymous, `403` when below the level) can submit a multipart `POST /upload-image` with the field `image`; `GET /upload-image` serves the same HTML shell as every other client path, and the upload form is rendered client-side.
`ImageUploadController::postAction` manually runs `ImageUploadValidator` (it is not a `ValidatedRequest`): the validator requires `files['image']` to be an array with `tmp_name` and `name` and requires `is_uploaded_file()`, ignoring the `error`, `size`, and MIME fields entirely; failure returns `400`.

On success the controller runs `file_get_contents(tmp_name)` (`false` returns `500`; the upload temporary directory must be in `FS_DIRECTORY_WHITELIST`), then gates on `ImageTypeDetectionFacade` (`Png`, `Jpeg`, `Avif` detectors, first match wins; `null` returns `400`).
PNG checks the first 4 bytes for `89504E47`, JPEG checks `FFD8FF`, and AVIF checks `ftypavif` or `ftypavis` at offset 4.
The detected type is otherwise discarded.

Accepted uploads call `ImageProcessorFacade` (`Png`, `Jpeg`, `Avif`, in that order) with `basename()` of the client-supplied name; each processor runs generic `imagecreatefromstring()` and then `ImageStorageService::storeImage()` with its fixed type into `IMAGE_STORAGE_DIR` (`private/upload/img`) under that basename.
That is three sequential overwrites of one path (`imagepng` quality 9, `imagejpeg` quality 100, `imageavif` quality 100): the final bytes are AVIF while the original basename and extension are preserved.
A same-name re-upload overwrites silently; a missing or disallowed directory, or an `imagecreatefromstring()` failure, throws and becomes `500`.
Success returns `201` with `{"filename": "<basename>"}`; the SPA shows the stored filename in a success message.
There is no public image-delivery route, upload quota, deduplication, or extension normalization; `private/` is not web-exposed.

`ext-gd` with PNG, JPEG, and AVIF support is required — AVIF support is required for every successful upload under the current configuration, not only "where used".
Image handling should be treated as experimental.
Functional tests must stub `ImageUploadValidator` because `is_uploaded_file()` fails outside real uploads.
