== Session handling

Session data is stored in the database through PHP's session handler. The
session cookie lasts 24 hours and is `HttpOnly` and `SameSite=Strict`; the
`Secure` flag is currently off, so HTTPS deployments should review that
setting.

At startup, a presented session ID is checked against stored sessions before
it is resumed. A valid resume refreshes the cookie's expiry for another 24
hours. Reads and writes also refresh the session's stored activity timestamp,
and garbage collection expires sessions only after 24 hours without activity,
matching the cookie lifetime. Session locking is not implemented.

The session user snapshot includes `AccessLevel`, the role used for
authorization. Protected requests reload the current user role from the
database, rather than trusting the snapshot alone; see
<<_precontrolleraction_chain>>.

Quick-tags visibility is also session-scoped: it defaults to off and is reset
when a user logs in (see <<_frontend_single_page_application>>).
