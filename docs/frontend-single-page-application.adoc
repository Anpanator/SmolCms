== Frontend (single-page application)

The frontend is a vanilla JavaScript SPA served from `public/`; it uses ES
modules and CSS with no framework, Node.js, or build step. The backend serves
the shell in `private/assets/index.html`, which loads the stylesheet and the
entry module into `#app`.

Client path constants live in `public/js/routes.js` and mirror the backend's
`RouteEnum`. `main.js` maps those paths to views, while `nav.js` builds the
navigation. Keep the path map, view wiring, and navigation in sync when adding
or renaming a page.

`api.js`, `router.js`, and `session.js` handle HTTP, history navigation, and
session state. Page modules live in `views/`; shared UI helpers include
`paginatedTable.js`, `moderationQueue.js`, `imageMetadata.js`, `tagLinks.js`,
and `searchForm.js`. `accessLevel.js` exports `hasAccessLevel()`, and
`validation.js` mirrors backend field rules for client feedback.

=== Upload and moderation behavior

The upload view sends each selected file sequentially as multipart field
`image[]`. The home view lists accepted-image thumbnails; the image view loads metadata and a protected sample, with a download link labeled *Download*.
Image and tag moderation queues act on the currently selected item: Approve
and Reject submit that selection, and a success message remains visible rather
than auto-dismissing.

Client-page deep links work on reload because their `GET` routes return the
same HTML shell. API errors are handled by status code; exception bodies are
normally empty, although development PHP settings may include a stack trace.
