== Running the application

The entry point is `src/app.php`. It handles the commands in
<<_cli_commands>>; HTTP requests require a web server with PHP-FPM or another
CGI-compatible PHP runtime.

Every configured `GET` route for a client page returns the same HTML shell,
which loads the SPA into `<div id="app"></div>`. API routes normally return
JSON; unmatched routes and framework errors are status responses, while
protected image delivery uses `X-Accel-Redirect` rather than a JSON body.

The reference Nginx configuration (`private/references/nginx.conf`) serves
`/public/` as static files, denies `/private/`, and sends other requests to
`src/app.php`. The Docker configuration follows the same boundary. Image
originals remain private, thumbnails are public static files, and sample and
download variants are private and delivered only through authenticated
internal Nginx locations (see <<_image_uploads>>).

For local smoke testing, run `./deploy.sh` to rebuild and replace the
`smolcms-dev` container, then verify changes against that deployment. See
link:docker/README.md[Docker images] for the container workflow.

=== Non-Docker PHP-FPM deployments

On a manual host, ensure PHP-FPM can write the runtime data directories. A
systemd `ProtectSystem` policy can make an application installed under `/usr`
read-only; use `private/references/php-fpm-override.conf` as a starting point
and include every writable path used by the deployment, including logs.

On a manual host, configure PHP errors to a host-selected log file writable by
PHP-FPM. Docker instead configures PHP to log under
`private/logs/php-error.log`.
