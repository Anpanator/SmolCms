[#_running_the_application]
== Running the application

The canonical entry point is `src/app.php`.
The application uses CLI mode for the commands documented in <<_cli_commands>>.
For HTTP requests, use a web server with PHP-FPM or another CGI-compatible PHP runtime.

The application is a JavaScript single-page application (SPA) backed by a JSON API.
The PHP backend serves only two kinds of HTTP responses: the same minimal static HTML shell for every client page (`GET /`, `/login`, `/register`, `/settings`, `/upload-image`), and JSON on every other route.
The shell loads `/public/css/main.css` and `/public/js/main.js` (an ES module), which render all views client-side into a `<div id="app"></div>` element.

`private/references/nginx.conf` contains a reference Nginx configuration.
Adapt its document roots and PHP-FPM socket for the target system.
It serves `/public/` as static files, denies `/private/` with 403, and forwards other requests to `src/app.php` via FastCGI.

The `public/` directory contains the SPA sources — vanilla JavaScript ES modules and the stylesheet — plus `layout_reference.html`, a static mockup of the real markup for styling reference.
It has no PHP entry point and requires no build step; nginx serves its files as-is.
Uploaded images are stored under `private/` and are not publicly served.

[#_systemd_sandboxing]
=== Systemd sandboxing and writable paths

On systems where `php-fpm` runs under a systemd unit with `ProtectSystem=full` (the Arch Linux default), the service's filesystem tree including `/usr` is mounted read-only.
Deploying the application below `/usr` (for example to `/usr/share/nginx/html`) therefore makes the SQLite database and the image storage read-only for PHP: reads succeed, but every write — user registration, session persistence on login, image upload — fails and surfaces as an empty `500` response (for login, the response status can flip to `500` even though the buffered `200` JSON body is still sent, because the failing session write happens during shutdown after output was buffered).

`private/references/php-fpm-override.conf` is a ready-to-use systemd drop-in that re-enables writes for exactly the writable paths (`private/db`, `private/upload/img`, `private/img`, and `public/img`) via `ReadWritePaths` while keeping the rest of the sandbox intact.
Install it as described in the file's header comment and restart `php-fpm`.

PHP errors are logged per `php.ini`'s `error_log` setting (default on this reference system: `/var/log/php_errors.log`); the file must exist and be writable by the FPM user (`touch /var/log/php_errors.log && chown http:http /var/log/php_errors.log`), otherwise logging silently does nothing.
