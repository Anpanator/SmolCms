== Routing

`RoutingConfiguration` registers `Route` objects using paths from
`RouteEnum`. A match requires both the URL path and HTTP method; routes are
checked in configuration order. A `{name}` path segment is passed to a
same-named handler argument. If no handler is specified, the method name
defaults to `getAction`, `postAction`, and so on.

[source,php]
----
new Route(
    path: RouteEnum::API_IMAGES->value,
    method: HttpMethod::GET,
    controller: ImageApiController::class,
    handler: 'getImageListAction',
),
----

Handlers accept a `$request` typed as `Request` or a readonly
`ValidatedRequest` subclass and return a `Response`. Client-page `GET` routes
serve the SPA shell; API handlers usually return `JsonResponse`. Protected
sample and download routes instead return a plain `Response` with
`X-Accel-Redirect` for Nginx file delivery.

When adding a page, register its `RouteEnum` case and server route, then update
the client path map and view wiring (and navigation when needed); see
<<_frontend_single_page_application>>. An unmatched path/method pair returns
`404`; see <<_error_handling_and_responses>> for handler errors.
