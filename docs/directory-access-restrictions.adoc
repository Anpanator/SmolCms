== Directory Access Restrictions

`FS_DIRECTORY_WHITELIST` in `config.php` is applied as PHP's `open_basedir`
restriction during startup. It covers the application trees PHP needs and
`PHP_TEMP_DIR`, so PHP's default upload temporary directory is available. If
`upload_tmp_dir` is overridden, its location must also be inside the
restriction; Docker points it into the already-allowed private tree.

This is defense in depth, not process-start isolation: constants, configuration,
Composer, and the initial service graph are loaded before the startup action
applies it. A host-level `open_basedir` can only be narrowed at runtime, and
this setting neither creates directories nor grants operating-system
permissions.

The application-level allowlist (`FS_APP_LEVEL_WHITELIST`) is separate and
cannot safely extend beyond PHP's restriction. Its roots must exist when
`FileSystemAccessService` is constructed; see <<_file_system_access>> and
<<_installation_and_setup>>.
