== Early startup configuration

The entry point first loads `constants.php`, `config.php`, and Composer's
autoloader. It then builds the service container and resolves
`ApplicationCore`; only after that does `ApplicationCore::init()` run the
startup actions in order.

To add an action, implement `StartupAction` and append its service identifier
to the `ApplicationStartupHandler` definition in
`CoreServiceConfiguration`:

[source,php]
----
new Service(
    identifier: ApplicationStartupHandler::class,
    parameters: [
        RestrictDirectoryAccessStartupAction::class,
        RegisterSessionHandlerStartupAction::class,
        ResumeSessionStartupAction::class,
        SetCrossOriginResourcePolicyStartupAction::class,
        MyStartupAction::class,
    ],
),
----

The action identifiers are resolved while `getService(ApplicationCore::class)`
builds the graph, then run by `init()`. Class-typed dependencies use service
identifiers and autowiring; builtin or untyped constructor arguments need an
explicit service definition with raw values (see <<_configuring_services>>).
`ApplicationStartupHandler` receives actions variadically, so list each action
identifier as its own positional parameter.
