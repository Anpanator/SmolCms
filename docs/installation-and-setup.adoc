== Installation and setup

Install the Composer dependencies from the repository root:

[source,shell]
----
composer install
----

=== Manual-host setup

This section covers a direct host install. For the container workflow, see
link:docker/README.md[Docker images].

The roots in `FS_APP_LEVEL_WHITELIST` (`config.php`) must exist before the
application starts. Tracked files and placeholders provide them in a checkout;
in particular, `private/upload/.gitkeep` creates `private/upload`, not
`private/upload/img`. The SQLite database and application logs also need their
directories, `private/db` and `private/logs`.

`ImageStorageService` creates missing image-storage directories on the first
write, including `private/upload/img` and the thumbnail, sample, download, and
checksum subdirectories. The parent allowlisted roots must already exist.

PHP-FPM needs read access to the application and write access to the database,
logs, upload tree, generated image stores, and PHP's upload temporary directory.
The CLI user needs corresponding access for commands it runs; in particular,
write access to `private/sql` is needed to generate migrations, and to
`private/assets` to refresh script integrity attributes. The CLI worker also
needs write access to image stores when it runs `--process-images`. PHP's
upload temporary directory must be writable by PHP, readable by the
application, and included in `FS_DIRECTORY_WHITELIST`.
`config.php` includes `PHP_TEMP_DIR` by default; add a custom `upload_tmp_dir`
there if it is outside the existing whitelist. See
<<_directory_access_restrictions>> for the separate PHP restriction.

Initialize a new default SQLite database with `php src/app.php --init-db`.
Existing databases are left unchanged; see <<_cli_commands>> before applying
migrations or using the destructive reset option.
