[#_configuring_services]
== Configuring services

`CoreServiceConfiguration` holds service definitions keyed by identifier.
`ServiceRegistry` caches built objects by that same identifier, so one
identifier represents one shared instance; use distinct identifiers when a
class needs multiple instances. `ServiceBuilder::getService()` checks the
registry, then configuration, then autowires a class with resolvable
class-typed constructor dependencies.

Use an explicit `Service` definition when a constructor needs builtin or
untyped values, a chosen implementation, or an alternate identifier. In a
definition, constructor parameters are positional: class-typed positions take
service identifiers, while builtin or untyped positions take raw values. A
missing required raw argument can raise `ArgumentCountError` at construction.

[source,php]
----
new Service(
    identifier: ImageStorageService::class . '.thumb',
    class: ImageStorageService::class,
    parameters: [IMAGE_THUMB_DIR, FileSystemAccessService::class],
),
----

Here the storage path is a raw string and the filesystem service is resolved
by identifier. Service identifiers may name classes or be application-defined
strings.
