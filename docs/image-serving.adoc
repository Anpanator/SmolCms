== Image serving and review

This document is the contract for the image display and review APIs: protected
serving of the viewing and download images via `X-Accel-Redirect`, the public
and authenticated image query endpoints, and the moderation (review) endpoints.

=== Storage and URL layout recap

Every stored image file is named `<sha-256 hex checksum>.<extension>` under a
two-character subdirectory of its base directory (see
<<_image_uploads>> and `ImagePathLayout`).

* Thumbs: `IMAGE_THUMB_DIR = public/img/thumb`, filenames `{checksum}.avif` —
  **publicly served** by nginx as static files under `/public/img/thumb/<2chars>/<filename>`;
  there is no backend endpoint for thumbs.
* Samples (viewing images): `IMAGE_SAMPLE_DIR = private/img/sample`, filenames `{checksum}.webp` — private.
* Downloads: `IMAGE_DOWNLOAD_DIR = private/img/dl`, filenames `{checksum}.<jpeg|webp|avif>` — private.
* Originals: `IMAGE_STORAGE_DIR = private/upload/img` — private, only touched by rejection cleanup.

`private/` is never web-served (`docker/nginx.conf` returns `403` for `/private/`).
The sample and download images are delivered to logged-in users only, through
nginx internal redirects.

=== Protected file serving (X-Accel-Redirect)

`ImageFileController` (`src/Controller/ImageFileController.php`) exposes two GET
endpoints, both `#[Authenticated(AccessLevel::NOVICE)]` (401 when anonymous; 403
for below-NOVICE, which cannot occur because NOVICE is the lowest level):

|===
| Method | Path | Query parameter | Serves

| `GET` | `/api/image/sample` | `name` | viewing image from `private/img/sample`
| `GET` | `/api/image/download` | `name` | download image from `private/img/dl`, as attachment
|===

Processing steps:

. **Name validation.** `name` must match `^[a-f0-9]{64}\.(avif|webp|jpeg|png)$`
   (a bare `checksum.extension` basename). Path separators, `..`, empty values,
   uppercase hex, wrong lengths, and unknown extensions return `400` with an
   empty body.
. **Database lookup.** The row is found by `ImageEntityService::findOneBySampleFilename()`
   or `findOneByDownloadFilename()`. An unknown name returns `404` — the API does
   not disclose which image names exist.
. **Visibility rule.** Only `ACCEPTED` images are served to users below `MOD`;
   `MOD+` reviewers may also preview queued (`PENDING_REVIEW`) images.
   Violations answer `404` (not `403`) so the existence and review state of
   non-public images is not disclosed.
. **File existence.** The file must exist at
   `<base>/<first 2 name chars>/<name>`; a missing file returns `404`.
. **Response.** A `200` response with an **empty body** and these headers:

|===
| Header | Sample endpoint | Download endpoint

| `X-Accel-Redirect` | `/internal/img/sample/<2chars>/<name>` | `/internal/img/dl/<2chars>/<name>`
| `Content-Type` | mapped from the extension: `image/avif`, `image/webp`, `image/jpeg`, `image/png` | same
| `Content-Disposition` | not set | `attachment; filename="<name>"`
|===

nginx then delivers the file from an internal-only location (the PHP process
never streams the bytes):

[source,nginx]
----
location ^~ /internal/img/sample/ {
    internal;
    alias /var/www/html/private/img/sample/;
}

location ^~ /internal/img/dl/ {
    internal;
    alias /var/www/html/private/img/dl/;
}
----

`internal` makes direct client requests to `/internal/...` fail with `404`; only
`X-Accel-Redirect` responses from the backend can use them. The blocking rules
for `/private/` are unchanged. The bare-metal reference configuration in
`private/references/nginx.conf` mirrors these locations (with its own document
root `/usr/share/nginx/html`).

Thumbnails are referenced directly as `/public/img/thumb/<2chars>/<thumbFilename>`
and need no endpoint or authentication.

=== Image query APIs

`ImageApiController` (`src/Controller/ImageApiController.php`) provides the read
endpoints; `ImageQueryService` builds the response data.

`GET /api/images` — **public** (no authentication):

[source,json]
----
{"images": [{"id": 7, "thumbSrc": "/public/img/thumb/ab/ab89…c9.avif"}]}
----

Lists only `ACCEPTED` images, newest first (`upload_date` descending). `thumbSrc`
is `null` while an image has not been processed yet (this cannot happen for
`ACCEPTED` images under the normal lifecycle). An empty list is `{"images": []}`.

`GET /api/image/detail?id=<int>` — `#[Authenticated(AccessLevel::NOVICE)]` (401 anonymous):

[source,json]
----
{"image": {
    "id": 7,
    "uploadDate": "2026-10-19 10:30:00",
    "uploader": "Upload User",
    "width": 100,
    "height": 50,
    "format": "jpeg",
    "fileSize": 1234,
    "sampleSrc": "/api/image/sample?name=ab89…c9.webp",
    "downloadSrc": "/api/image/download?name=cd12…34.jpeg"
}}
----

`uploadDate` is formatted as `Y-m-d H:i:s`; `uploader` is the display name of the
uploading user (`UserService::findOneById`). `width`, `height`, `format`,
`fileSize`, `sampleSrc`, and `downloadSrc` are `null` while the image has not
been processed yet. The detail endpoint returns any known image (no status
filter) — the sensitive variants remain protected by the file-serving endpoints'
visibility rule. Responses: `200` with the data, `404` for an unknown id, `400`
for a missing/malformed id (not a positive-integer string).

=== Review backend

`ImageReviewController` + `ImageReviewService` (`src/Service/Image/ImageReviewService.php`),
all endpoints `#[Authenticated(AccessLevel::MOD)]` (401 anonymous, 403 below MOD).

`GET /api/review/queue` — all `PENDING_REVIEW` images, oldest first:

[source,json]
----
{"images": [{
    "id": 7,
    "thumbSrc": "/public/img/thumb/ab/ab89…c9.avif",
    "sampleSrc": "/api/image/sample?name=ab89…c9.webp",
    "uploadDate": "2026-10-19 10:30:00",
    "uploader": "Upload User"
}]}
----

`thumbSrc`/`sampleSrc` are `null` when the corresponding variant file name is not
set (yet).

`POST /api/review/approve?id=<int>`:

* Unknown id → `404` (empty body).
* Missing/malformed id → `400`.
* `PENDING_REVIEW` → status becomes `ACCEPTED`, response `204` (empty body).
* Any other status (e.g. already `ACCEPTED`) → **idempotent no-op**: `204`,
  row unchanged.

`POST /api/review/reject?id=<int>`:

* Unknown id → `404`; missing/malformed id → `400`.
* Deletes the database row **and** all related files: the original
  (`IMAGE_STORAGE_DIR/<2chars>/<checksum>.<originalExtension>`), thumb, sample,
  and download files. File deletion is best-effort: missing files are skipped
  and undeletable files are logged (warning) without aborting the row deletion.
* Response `204` (empty body).

The 204 responses use `JsonResponse(status: NO_CONTENT)` like `POST /logout`
(empty body, `Content-Type: application/json`).

=== Routes

All routes are registered in `RouteEnum`/`RoutingConfiguration` (see
<<_routing>>): the two client pages `IMAGE_DISPLAY = /image` (image display
view) and `IMAGE_REVIEW = /review` (review view) serve the SPA shell via
`IndexController::getAction`, plus the API endpoints `API_IMAGES`,
`API_IMAGE_DETAIL`, `API_IMAGE_SAMPLE`, `API_IMAGE_DOWNLOAD`,
`API_REVIEW_QUEUE`, `API_REVIEW_APPROVE`, and `API_REVIEW_REJECT`.
